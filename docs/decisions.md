- 2026-11-11 — **Gemini voice fallback** (approved by the owner; deviates from AGENTS.md §3 "one Gemini call per answer" for voice answers made WITHOUT browser speech recognition, e.g. Firefox). Browsers with `SpeechRecognition` keep the free on-device-vendor path. Otherwise the app records the mic itself (`src/ui/wavRecorder.ts`: browser echo/noise/auto-gain, 100 Hz-7 kHz filter, AudioWorklet capture), cleans it (`src/ui/wav.ts`: resample to 16 kHz mono, trim silence, normalise, WAV) and sends it to Gemini (`src/adapters/firebase/transcribe.ts`, strict "[no speech]" prompt, temperature 0, 20 s timeout, 1 retry, 4 MB / 90 s caps). The transcript is ALWAYS shown in the box for review before the normal single evaluation call; it is never auto-sent. Audio is never stored. Silence is dropped client-side so the model is never asked to guess. WAV was chosen over browser WebM/MP4 because it is a format Gemini documents support for and could be tested. Evidence so far (one-off checks, not a recorded eval): the API accepted our WAV and returned "[no speech]" for silence 3/3 and for a speech-free tone 1/1, 2.2-5.6 s (one earlier 24 s outlier with the first, weaker prompt, which also INVENTED a sentence from silence). NOT yet tested: real speech, accents, Pidgin, word-error rate, Safari/Firefox on real devices. Privacy page updated.
- 2026-11-11 — **Browser dictation removed; voice is now recording + Gemini only** (owner request). Deleted `useSpeechInput`, `useMicLevels`, `joinSegments`, the touch-only "speaking signal" bars and the browser engine in `useVoiceEntry`; read-aloud (speech synthesis) stays. One path on every browser that has `AudioWorklet` + `getUserMedia`; others get a disabled mic. The round Send button now transcribes AND submits in one tap; ✓ puts the transcript in the box for review first. **Why transcription is not folded into the evaluation call ("under the hood" in a single call):** the engine must have the TEXT before scoring, because distress detection (AGENTS §6), skip/repeat/end commands, empty-answer handling, the injection wrapper and local VADER sentiment all run locally on text first (AGENTS §3: control flow stays deterministic). Audio-in-evaluation would skip those. It would also save little: audio tokens are paid once either way, so the saving is one request (quota/latency, roughly 2-5 s), not tokens. Cost per voice answer is therefore one transcription call plus the normal evaluation call, both on the free-tier request quota; per-second audio token rate and prices are NOT verified here. Cost levers already in place: silence trimmed, 16 kHz mono, 90 s cap, nothing sent when silent.
